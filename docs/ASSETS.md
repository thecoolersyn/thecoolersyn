# Assets

Every visual in the README is a standalone, hand-editable SVG with SMIL
animation. No JavaScript, no build step, no external requests — which is
exactly why they work inside GitHub's README renderer.

---

## How animation works here (and why it works at all)

GitHub renders images through an image proxy and **strips `<script>`,
`<foreignObject>` and inline event handlers**. What survives is a static SVG
document, which the browser renders as an image — and images *do* run SMIL
animation. So every moving thing in this repo is a SMIL element:

| Element | What it does here |
|---|---|
| `<animate>` | tweens one attribute (opacity, width, stroke-dashoffset) |
| `<animateTransform>` | moves / rotates / scales an element |
| `<animateMotion>` | travels an element along a path |
| `calcMode="spline"` + `keySplines` | smooth easing, `0.4 0 0.2 1` everywhere |
| `begin="-1.7s"` | **negative** start time — begins mid-cycle, so nothing is blank on load |
| `calcMode="discrete"` | switches text/values instantly (used for changing digits) |

Two consequences worth internalising:

1. **You cannot animate text content.** To change a number, stack several
   `<text>` elements and toggle their `opacity` with `calcMode="discrete"`.
   See `assets/systems/agent-loop.svg` for the working pattern.
2. **A `clipPath` rect is positioned in the element's own coordinates.** To
   make a line "type" itself, animate the clip rect's `width` from 0. The rect
   must sit at the text's `x`/`y`, not at `0,0` — this is the single most
   common bug in this kind of asset.

## Editing an asset

**The safe way: change values, never structure.**

- Colours: use only the tokens in [`../DESIGN_SYSTEM.md`](../DESIGN_SYSTEM.md).
  To retheme globally, find-and-replace the hex values across `assets/`.
- Animation speed: change the `dur="…"` values. `4s`–`14s` is the range the
  whole design is tuned for. `dur` under `2s` reads as frantic.
- Loop timing: the `keyTimes` list controls the shape of each cycle. They must
  be evenly spaced between `0` and `1` and the same length as `values`.
- Text content: safe to edit. Watch the character budget — a 4px grid means a
  longer string will overrun the card border.

**Structural elements that break the design if you move them:** card
outlines, the 4px grid, label baselines, and the footer disclaimer lines.

`assets/stack/stack.svg` and `assets/projects/projects.svg` have
`<!-- EDIT:…:BEGIN -->` / `<!-- EDIT:…:END -->` markers around every
replaceable block. Edit only inside those.

### Simulated-content markers — do not remove

Every invented number carries a visible honesty marker, by design:

| Asset | Marker |
|---|---|
| `dashboard.svg` | footer: `DEMO · simulated telemetry — not live system data` |
| `commit-graph.svg` | none needed — it is **real** data. Carries a `LIVE` chip, asserted by CI. |
| `markets.svg` | header `SIMULATED` + `not investment data · not financial advice` |
| `orderflow.svg` | `SIMULATED` + `synthetic feed · not market data` |
| `systems.svg` | `SIM` chip + `simulated runtime metrics · not a live trace` |
| `agent-loop.svg` | `illustrative` tag; loop budget is a concept, not a measurement |

These are not decoration. Keep them when editing. The finance panel
specifically must never imply returns, P&L, portfolio value or performance —
if you add a "real" number there, it is a false financial claim.

## Updating the animated assets

**Most assets: nothing to do.** They are static files; they animate in the
browser forever. Edit, save, push.

**`commit-graph.svg` is generated from real GitHub data.** Never hand-edit it.

```bash
GITHUB_TOKEN=... python3 scripts/gen_commit_graph.py --login YOUR_HANDLE
python3 scripts/gen_commit_graph.py --from-json payload.json   # offline, for testing
```

It reads the public contribution calendar over the GraphQL API. There is **no
synthetic fallback**: if the fetch fails the script exits non-zero and leaves
the committed SVG untouched, so a failed run can never replace real data with a
fabricated pattern. Output is deterministic for a given payload, so the weekly
workflow only commits when the data actually changed.

Refresh it on demand: **repo → Actions → Update contribution graph → Run workflow**.
It also runs every Monday at 05:43 UTC.

### Refreshing the real GitHub statistics

Committed automatically by [`.github/workflows/stats.yml`](../.github/workflows/stats.yml),
daily. To force a refresh: **repo → Actions → Update README cards → Run workflow**.

The two files in `assets/stats/live/` are **placeholders until that workflow
runs once**. They are deliberately committed so the README never shows a
broken image. Do not hand-edit them; the workflow overwrites them.

## Verify your changes

```bash
bash scripts/build.sh          # validate XML, size, GitHub-stripped tags, README wiring
bash scripts/build.sh --strict # also fail on size warnings
bash scripts/preview.sh        # list assets (does not block)
bash scripts/preview.sh --serve   # serve on :8080 and watch the animation
```

`build.sh` fails on: malformed XML, missing `role="img"`, `<script>`,
`<foreignObject>`, `@font-face`, inline handlers, `javascript:`, external
`href`, and anything over 80KB. It also checks that every `assets/…` path
referenced by `README.md` actually exists.

### Exporting to GIF (rarely needed)

Prefer keeping SVG: it is sharper, ~50× smaller, and the animation is smooth.
SMIL does **not** survive a GIF export anyway — a rasteriser would flatten each
frame, so the result is a slideshow, not a loop.

If you truly need a GIF fallback:

```bash
# 1. rasterise frames with a headless browser (Chrome/Chromium must be installed)
for i in $(seq 0 49); do
  google-chrome --headless --screenshot="f$i.png" --window-size=1200,420 \
    --virtual-time-budget=$((i * 200)) "file://$PWD/assets/hero/hero.svg"
done
# 2. assemble
ffmpeg -framerate 25 -i f%d.png -loop 0 -vf "scale=800:-1,palettegen=stats_mode=diff" \
  -y /tmp/palette.png
ffmpeg -framerate 25 -i f%d.png -i /tmp/palette.png -loop 0 -lavfi \
  "paletteuse,dither=bayer" hero.gif
```

Keep the result under ~2MB, or the README loads slowly. Do not commit both an
SVG and a GIF for the same slot — pick one.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Blank / invisible image | missing `width`, `height` or `viewBox` on the root `<svg>` | set all three; `width`/`height` are for the `<img>` intrinsic size, `viewBox` for the coordinate system |
| Image shows but does not move | `<script>` used instead of SMIL, or all `begin` values are positive | GitHub strips `<script>` — rewrite as SMIL; use negative `begin` so it is mid-cycle on first paint |
| White box | no background `<rect>` | every asset opens with `<rect width="…" height="…" fill="#05070A"/>` |
| Text "types" but is invisible | `clipPath` rect at `x="0"` while the text is at `x="60"` | the clip is in user space — align the rect with the text |
| Two elements overlap and flicker | both are opaque at the same `keyTimes` | use `calcMode="discrete"`, or make one start at opacity `0` |
| Wrong colours after a global find/replace | a hardcoded hex outside the token set | check `DESIGN_SYSTEM.md`; there is no other allowed palette |
| Very slow page load | total asset bytes too high | `bash scripts/build.sh`; keep each file under 40KB |
| Animation stutters | more than ~14 animated elements in one file | drop to a few well-chosen ones; see the design system |
